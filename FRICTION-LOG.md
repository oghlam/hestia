# HESTIA Friction Log

> Real implementation friction encountered while integrating Ring Appstore webhooks, AWS Bedrock Nova Micro, and AWS DynamoDB/EC2 for the HESTIA elder-care pipeline. Only AWS / Ring API / SDK / Bedrock model issues are logged — UI/design friction is intentionally excluded.

## Entries

| ID | Area | Friction | Impact | Workaround / Resolution | Status |
|---|---|---|---|---|---|
| **F-001** | **Ring Webhook HMAC — Raw Body Capture** | `express.json()` parses the body before verification, mutating whitespace and breaking `X-Signature: sha256=<hex>` HMAC-SHA256. | Every Ring Cloud webhook returned `401 Unauthorized` even with a valid signing key. | Capture `req.rawBody` Buffer via `express.json({ verify: (req,_res,buf)=> req.rawBody=buf })` in `server/index.ts:124` and verify with constant-time `crypto.timingSafeEqual` in `server/ring-adapter.ts:56` against `RING_HMAC_SIGNING_KEY` raw UTF-8 bytes. | ✅ Resolved |
| **F-002** | **AWS Bedrock Nova Micro — Latency & Offline Jitter** | Bedrock `amazon.nova-micro-v1:0` calls add 400ms–2s tail latency on S3/S4 critical alerts; endpoint occasionally unreachable from dev network. | UI stalled and caregiver dispatch was blocked waiting for AI summary. | Wrap Bedrock call with `AbortController` 3000ms timeout in `server/bedrock-service.ts:62`, use deterministic `generateDeterministicSummary()` fallback. Store `provider: bedrock_nova_micro | deterministic_fallback` so pipeline never blocks. | ✅ Resolved |
| **F-003** | **AWS DynamoDB — Hybrid Local ↔ Cloud Dual-Mode** | Dev machines have no AWS credentials, yet production requires `hestia_elder_care_prod` on `us-east-1`. Direct SDK import crashes offline and `EntityTypeIndex` GSI provisioning differs between local and cloud. | App failed to boot offline; sync between local memory and DynamoDB was lossy. | Lazy-load `@aws-sdk/client-dynamodb` + `@aws-sdk/util-dynamodb` in `server/dynamo-service.ts:25`, fallback to in-memory `mockDynamoTable` when SDK/client missing. `ensureDynamoTable` handles `ResourceNotFoundException` vs `ResourceInUseException`, provisions GSI `EntityTypeIndex` (5 RCU/WCU), and `putEntityItem` falls back to mock on throw. Exposed via `POST /api/settings/db-test` MFA + `POST /api/settings/db-sync/*` bidirectional sync in `server/store.ts:1168`. | ✅ Resolved |
| **F-004** | **Ring Appstore Webhook v1.1 — Schema Drift & Deduplication** | Ring v1.1 payload nests data in `meta`/`data.attributes` with varying `data.type` (`motion_detected`, `button_press`, `device_online`, `tamper_*`) and unreliable device IDs; duplicate `meta.request_id` resent on retries. | Events mapped to wrong room or double-triggered S3 alerts. | Centralize in `server/ring-adapter.ts:76` `normalizeRingWebhook()` with `DEFAULT_DEVICE_ROOMS` + heuristic fallback (`bedroom`/`corridor`/`entry`/`living_room`), normalize `data.type` → `RingEventType`, and deduplicate via `isDuplicateRequest(requestId)` Set in `server/store.ts:677` checked in `POST /webhooks/ring` `server/index.ts:1014`. | ✅ Resolved |
| **F-005** | **AWS Bedrock Nova Micro — Text-Only Contract & LiteLLM Bridge** | Nova Micro accepts **structured text only**; sending image/video/base64 causes 400. Team initially tried to pipe Ring snapshot bytes to Bedrock. Also two env paths (`BEDROCK_ENDPOINT` vs `LITELLM_ENDPOINT/chat/completions`) with different auth. | Model rejected requests; image privacy risk and token waste. | Enforce boundary in `server/bedrock-service.ts:14` `buildNovaMicroPrompt()` — only `scene/room/subject/signals` text. Image stays local via `server/vision-service.ts` 64-d matcher. Bridge in `server/bedrock-service.ts:56` resolves `BEDROCK_ENDPOINT ?? LITELLM_ENDPOINT + /chat/completions`, sends `model: amazon.nova-micro-v1:0, temperature 0.2, max_tokens 100`. | ✅ Resolved |
| **F-006** | **AWS EC2 kurusetra — Public HTTPS for Ring Cloud Webhooks** | Ring Cloud only delivers to public HTTPS `POST /webhooks/ring`; local `127.0.0.1:8787` is unreachable. EC2 must serve both API and Vite `dist` with CORS. | No live Ring hardware could reach HESTIA during development. | Deploy to `kurusetra` `us-east-1` with `https://32-193-23-154.nip.io/webhooks/ring` `HESTIA-PROGRESS.md:265`, enable `cors()` and `express.static(dist)` + SPA fallback `server/index.ts:103` `app.get(/^\/(?!api\/).*$/ )`, and verify via `POST /webhooks/ring` HMAC diagnostic from Settings → Webhook Test. | ✅ Resolved |

## Categories

- **Ring API / SDK & Ingestion**: HMAC-SHA256 raw-body verification, v1.1 payload normalization, `request_id` idempotency, HTTPS webhook exposure on EC2.
- **AWS Bedrock (Nova Micro)**: Text-only prompt contract, LiteLLM bridge, 3s abort timeout, deterministic fallback, `temperature 0.2 / max_tokens 100`.
- **AWS DynamoDB & EC2**: Lazy SDK loading, `ensureDynamoTable` with `EntityTypeIndex` GSI, offline mock fallback, bidirectional Local ↔ Cloud sync, EC2 `kurusetra` hosting.
